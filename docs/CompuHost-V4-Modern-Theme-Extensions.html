Overview

The package modernizes native Clarion windows while preserving normal Clarion events and control FEQs. It supports:

Dark and light themesMultiple UI threads Per-window backgroundsButtons and icons LIST headersSHEET tabs OPTION controlsSlidersMenus

The preferred workflow is template-driven. Add the Global extension once, then add the Window extension to each window procedure. Advanced extensions are only needed when automatic discovery is insufficient or a control needs an override.

Clarion remains authoritative. Captions, icons, enabled/hidden state, focus, tab order, default buttons, accelerators, control placement, and application events continue to originate in Clarion.

Installation

  1. Close running applications that are using CHTheme.dll or ButtonSubclass.dll.
  2. Place CHModernTheme.tpl in the Clarion 10 accessory template win folder.
  3. Place the DLLs in accessory\bin, import libraries in accessory\lib, and the CHModern*.inc/.clw files in accessory\libsrc\win.
  4. In Clarion, open Tools → Template Registry, register or refresh CHModernTheme.tpl, then reopen the application if necessary.
  5. Regenerate and rebuild the application.
The registered repository DLLs are copied into the generated project when the application is generated. This refreshes older project-local copies and ensures the runtime DLLs are copied beside the executable.

Quick start

  1. Add CompuHost V4 Modern Theme – Global to Global Extensions.
  2. Choose the default theme and global light/dark window backgrounds.
  3. Add CompuHost V4 Modern Theme – Window to each window procedure.
  4. Leave automatic controls, buttons, menus, LISTs, SHEETs, and OPTIONs enabled initially.
  5. Use the exclusion lists for controls that must retain their original rendering or application colors.
  6. Regenerate, rebuild, and test both themes.

CompuHost V4 implementation

CompuHost V4 uses the template-generated integration; application embeds are not required for ordinary theme, button, LIST, SHEET, OPTION, or slider operation.

  1. Add CompuHost V4 Modern Theme – Global once at the application level.
  2. Add CompuHost V4 Modern Theme – Window to each participating window procedure, including the main frame and separately threaded or modal windows.
  3. Leave automatic BUTTON, LIST, SHEET, OPTION, menu, and control discovery enabled unless a documented exclusion or advanced override is required.
  4. For each native slider, add Slider REGION (manual configuration) and assign the Clarion REGION that owns its position and visibility.
  5. Keep Clarion authoritative for saved SHEET selection and ordinary TAB contents. Restore a saved page with normal Clarion selection code; the helper mirrors that choice to the custom blue tab highlight.
  6. Regenerate after updating the registered template, helper source, import libraries, or runtime DLLs, then perform a Win32 Release build.
Current ownership rules: Clarion controls ordinary TAB contents; the native strip mirrors Clarion except when the user clicks the strip; each slider overlay follows its assigned REGION and relevant TAB/container ancestors.

Initialization and saved window positions

The template generates window startup in this order: OPEN(Window), WinResize.Init(...), theme attachment and themed-control initialization, then INIRestoreWindow(...). This allows WindowResizeClass to capture the original Clarion geometry before theme attachment or control refreshes occur.

After INI restoration, the extension requests the required final resize and theme refresh. Fully off-screen top-level windows are moved onto the primary monitor; MDI children are kept within their parent client area. Normal saved positions that remain visible are preserved.

BUTTON settings

Use CompuHost V4 Modern Theme – BUTTON settings once per button requiring a role or metric override.

RoleTypical use
StandardOrdinary commands.
PrimaryThe principal action in a window.

SelectedA latched or currently selected command.

Optional metrics are corner radius, border width, and gradient use. Role colors do not change keyboard behavior: enabled buttons retain Tab focus, Space/Enter activation, default-button behavior, and Clarion accelerators.

Captions, icons, and alignment

  • A file icon set in the designer and a Clarion icon handle are both supported.
  • Icon size scales from the button height.
  • Disabled icons are dimmed with the disabled button state.
  • Centered icon-and-caption buttons stack the icon above the caption.
  • Left/right buttons place the icon on the corresponding outer edge.
  • A multiline caption uses a real carriage-return/line-feed sequence.
! Multiline caption
?GoButton{PROP:Text} = 'Start<13,10>Playback'
DISPLAY(?GoButton)

! Mnemonic: displays GO with O underlined and activates with Alt+O
?GoButton{PROP:Text} = 'G&O'
DISPLAY(?GoButton)
A global shortcut owned by another Windows application can intercept an Alt-key combination before Clarion receives it. Choose another mnemonic or change the conflicting global shortcut.

Runtime alignment

Runtime changes to Clarion PROP:Left, PROP:Center, or PROP:Right are not reliably reflected in the underlying Win32 style. Use:

! Horizontal: -1 left, 0 center, 1 right
! Vertical:   -1 top,  0 center, 1 bottom
CHButton_SetContentAlignment(?GoButton{PROP:Handle}, 1, 0)
DISPLAY(?GoButton)

LIST controls

Automatic LIST discovery reads each Clarion FORMAT and creates a modern header. Set the default header height in the Window extension.

Use the LIST (advanced override) extension when a manually managed helper or a runtime column definition is required. Supply:

  • A unique helper instance label.
  • The LIST FEQ.
  • A CSTRING containing the column definition.
  • Optional setup code and the header height.

The helper handles header clicks, sort indicators, resized columns, column widths, and cleanup through the normal accept loop.

Header-click events

Clicking a themed header posts EVENT:Accepted to the source LIST. Read the clicked column from the automatically generated helper. The result is one-based; zero means the acceptance was not an unread header click. Reading the value clears it, so call GetHeaderClick() once and retain the result.

ClickedColumn LONG

! In the EVENT:Accepted handling for ?DJPlaylist
OF ?DJPlaylist
  ClickedColumn = CHModernTheme:List:DJPlaylist.GetHeaderClick()
  IF ClickedColumn
    CASE ClickedColumn
    OF 1
      ! Title header clicked
    OF 2
      ! Duration header clicked
    END
  ELSE
    ! Ordinary LIST acceptance, not a header click
  END
Automatic helper naming: a LIST named ?DJPlaylist uses CHModernTheme:List:DJPlaylist. Do not call a global GetHeaderClick procedure; it is a method of that generated helper instance.

Resizable and fixed columns

During initialization, the helper reads ListFEQ{PROPLIST:Resize,Column} for every column and passes that setting to the themed header. A divider is draggable only when the preceding Clarion column is resizable. Columns configured as non-resizable in the LIST FORMAT/designer therefore remain fixed without application embeds.

When a permitted divider is dragged, the helper writes the new width back to PROPLIST:Width and refreshes the LIST. This keeps Clarion's column definition authoritative.

Scrollbars

Vertical LIST scrolling follows the themed Clarion LIST rendering. Clarion creates a horizontal scrollbar as a separate runtime-managed Windows control whose private drag loop repaints native system colors. Paint overlays caused visible flashing while dragging and are intentionally disabled in the stable DLL. Avoid horizontal LIST scrollbars where practical. A fully themed horizontal bar will require a future complete custom scrollbar replacement.

SHEET controls

Automatic SHEET discovery derives tab captions and TAB FEQs directly from the window. It maintains the custom strip position, selected highlight, tab visibility/enabled state, resizing, runtime captions, content background, and theme changes.

Clarion remains solely responsible for ordinary TAB-content visibility. A programmatic or saved Clarion selection is mirrored to the custom strip. Only a genuine click notification from the custom strip drives PROP:ChoiceFEQ back into Clarion. A zero PROP:ChoiceFEQ is never forced to the first TAB.

The Window extension supplies the default header height and light/dark content backgrounds. Add SHEET (advanced override) only when a particular SHEET needs different content backgrounds.

! Examples using the automatically generated helper name
CHModernTheme:Sheet:SHEET1.SetSelected(2)
CHModernTheme:Sheet:SHEET1.SetEnabled(3,FALSE)
CHModernTheme:SheetLabels:SHEET1 = 'General|Playback|Advanced'
CHModernTheme:Sheet:SHEET1.SetLabels(CHModernTheme:SheetLabels:SHEET1)
The helper supports up to 20 mapped TAB controls per SHEET. Do not add application code that manually hides all controls belonging to inactive TABs; normal Clarion SHEET behavior is authoritative.

OPTION and RADIO controls

Automatic OPTION discovery derives RADIO captions and FEQs. The flat modern renderer tracks checked, unchecked, focused, and disabled states while the Clarion OPTION value remains authoritative.

Use Flat OPTION (advanced override) for a manually selected OPTION control or helper instance. Up to 20 RADIO choices can be mapped per helper.

Slider REGION extension

The slider is hosted over a Clarion REGION so the application keeps a stable FEQ and resize anchor. Configure orientation, minimum, maximum, initial value, step, and separate track/fill colors for light and dark themes.

VolumeSlider.SetRange(0,100)
VolumeSlider.SetValue(65)
VolumeSlider.SetStep(5)
VolumeSlider.SetEnabled(TRUE)
CurrentVolume = VolumeSlider.GetValue()

VolumeSlider.SetColors(LightTrack,LightFill,DarkTrack,DarkFill)

The knob is rendered independently from the configured track and fill colors. Keyboard input and minimum/maximum positions are handled by the native slider window.

The Win32 slider is a child of the Clarion window rather than the REGION itself, so it cannot inherit TAB clipping automatically. The helper starts the overlay hidden, then evaluates the assigned REGION, its PROP:Hide state, its Clarion parent chain, and the enclosing SHEET's PROP:ChoiceFEQ. This prevents EQ sliders from appearing on InstaTunes, AudioBits, VideoBits, or another inactive page without changing the SHEET selection or hiding ordinary controls.

Menus

When enabled, the Window extension derives the native Clarion menu recursively. It preserves items, nested submenus, separators, disabled and checked states, keyboard navigation, and configured menu icons.

Menu colors are theme colors; they do not derive from a custom window background.

Runtime theme changes

Use the application wrapper to change every attached window, including windows on other Clarion UI threads:

! Dark
CHModernTheme_SetApplicationTheme(0,CHTHEME_DARK)

! Light
CHModernTheme_SetApplicationTheme(0,CHTHEME_LIGHT)

The DLL distributes the change safely to each owning UI thread. Each window retains its individual extension options, exclusions, and background overrides. Windows opened after a change read the current application mode when attached.

To repaint a specific attached window without changing its mode:

CHModernTheme_Refresh(0{PROP:Handle})

Deployment

Files required with the deployed application

The following runtime files must be installed in the same folder as the compiled Clarion application executable:

FileRequiredPurpose
CHTheme.dllYesProvides window, menu, LIST, SHEET, OPTION, slider, theme propagation, and repaint support.
ButtonSubclass.dllYesProvides modern BUTTON rendering, roles, icons, focus indication, runtime alignment, and button state handling.
Deployment rule: distribute both DLLs beside every EXE that uses these extensions. The customer does not need the template, import libraries, include files, helper source, PDB files, or Visual Studio runtime project files.

Application-owned resources

Also deploy any resources referenced by the application at runtime:

  • File-based .ico files used by buttons, unless they are embedded or already copied by the application project.
  • Other images, help files, configuration files, or application data required by the Clarion program.

Clarion API icons such as ICON:Hand do not require a separate icon file.

Files required only on the development computer

The Global extension adds the required libraries, helper source files, and DLL deployment items to the generated project. During generation it first refreshes project-local copies from the registered Clarion accessory repository.

Release checklist

  1. Install the current registered DLLs and support files into the Clarion accessory repository.
  2. Regenerate the application so the extension refreshes its project-local dependencies.
  3. Perform a clean Release build.
  4. Confirm CHTheme.dll and ButtonSubclass.dll are beside the Release EXE.
  5. Include both DLLs in the installer or deployment package.
  6. Include any file-based button icons or other application-owned resources.
  7. Test the packaged application on a computer that does not have the Clarion development environment installed.
After updating a registered DLL or helper source, regenerate the application before rebuilding. A normal build alone may continue using an older project-local copy.

Recommended test checklist

  • Dark → Light → Dark repeatedly with multiple windows open.
  • Frame, MDI child, separate threaded window, and modal dialog.
  • Open a new window after changing the theme.
  • Minimize/restore, maximize, and rapid resizing.
  • Button focus by Tab; activation by Space, Enter, default button, and Alt mnemonic.
  • Runtime captions, icons, enabled/hidden state, resizing, roles, colors, and alignment.
  • LIST selection, disabled state, vertical scrolling, many rows, header-click events, resizable columns, and fixed columns.
  • SHEET tab selection, disabled/hidden tabs, captions, resizing, and content backgrounds.
  • Restart with each CompuHost V4 TAB saved in turn; confirm the restored contents and blue custom-strip highlight agree immediately.
  • Restart on a non-slider TAB; confirm its ordinary controls remain visible and all EQ slider overlays remain hidden.
  • Switch repeatedly between EQ, InstaTunes, AudioBits, and VideoBits after hovering, focusing, or dragging a slider.
  • OPTION/RADIO checked, unchecked, disabled, and focused states.
  • Horizontal/vertical sliders, keyboard movement, range endpoints, disabled state, and runtime colors.
  • Menus with disabled/checked items, separators, submenus, keyboard navigation, and icons.
  • DPI at 100%, 125%, 150%, and 200%; monitor move and Remote Desktop reconnect.
  • An excluded control beside a themed equivalent.
  • Application-defined colors and fonts with selective preservation.

Troubleshooting

The DLL in a project is old

Confirm the newest DLL is in accessory\bin, then regenerate the application. The Global extension refreshes the project-local dependency during generation.

Duplicate symbols

Remove older button/theming extensions or manually added copies of the same import library. The modern Global extension already adds its dependencies.

A window changes only when activated

Ensure the Window extension is present on that procedure and that the project has been regenerated with the current template and DLLs.

A SHEET background changes only after another repaint

Regenerate and verify that both the current CHModernSheet helper and CHTheme.dll were copied into the project/output.

The restored TAB contents are correct but the blue highlight is wrong

Regenerate with the current CHModernSheet.clw. The current helper mirrors Clarion's programmatic or saved PROP:ChoiceFEQ to the native strip while reserving strip-to-Clarion changes for genuine strip-click notifications.

The selected TAB is blank until another TAB is clicked

Verify that the current CHModernSheet.clw is in both the Clarion library source and generated project. Older revisions manually changed PROP:Hide on ordinary TAB controls during registration; the current helper leaves content visibility to Clarion.

Sliders appear on TABs that do not own them

Confirm every slider extension is assigned to its correct Clarion REGION and that the project contains the current CHModernSlider.clw/.inc. The helper evaluates the REGION and enclosing TAB/SHEET hierarchy before showing the native overlay.

An Alt accelerator activates another application

The other application owns a global shortcut. Change that shortcut or choose a different mnemonic. Also verify that runtime code does not overwrite the designer caption with a differently placed ampersand.

Runtime left/center/right has no effect

Call CHButton_SetContentAlignment; Clarion runtime alignment properties do not reliably update the native button style after attachment.
