CompuHost V4 Promo-Trailer Designer

Clarion 10 integration, file ownership, callback processing, and release-candidate testing.

Updated August 8, 2026 · Promo ABI 00010000H · Data record 4,256 bytes · Text capacity 4,096 bytes

Purpose and ownership

CHTheme.dll supplies a modeless, themed Promo-Trailer editor with per-line formatting, colors, Undo/Redo, Clear, Auto-load selection, and integrated .PRM Load/Save dialogs. Each nonblank physical line is one Promo-Trailer and advances on the next online scrolling rotation.

CompuHost V4 rule: the returned encoded text is authoritative. Preserve <APP>, <NOAPP>, color, Bold, Italic, and Underline tags. V4 uses the DLL's file-based .PRM workflow and must not rebuild the legacy CompuHost V3 Promo queue.

Clarion owns the caller-provided data record until the modeless designer closes. The DLL owns the editor window, file dialogs, remembered .PRM folder, and safe window placement.

CompuHost V4 implementation - concise checklist

  1. Confirm the release-candidate CHTheme.dll, CHTheme.lib, and CHPromoDesignerTypes.inc are in the CompuHost V4 project/runtime locations.
  2. Confirm the CompuHost V4 Modern Theme - Global extension is present. It generates the Promo include and all five CHPT_... MAP imports automatically.
  3. Regenerate once after installing the updated template so its generated declarations and project-copy directives are refreshed.
  4. Add the exact 4,256-byte PromoData group and state variables to the procedure that owns the existing Promo-Trailer command.
  5. Reuse an existing hidden callback button or add ?CHUIComplete; it must remain alive while the designer is open.
  6. In the existing Promo-Trailer command's EVENT:Accepted, prepare the data, validate the ABI, and call CHPT_OpenDesigner.
  7. At the beginning of ?CHUIComplete / EVENT:Accepted, consume Promo completion. On OK, copy the complete PromoData.Text, read the Auto-load flag, set GLO:PromoChanged, and post Event:ResetRotationScroller.
  8. Do not test the old RTF field, parse individual lines, strip routing tags, or load the former Promo queue.
  9. Prevent the owner window from closing while PromoDesignerInstance is nonzero.
  10. Regenerate and compile CompuHost V4 Win32 Release, then perform the acceptance tests at the end of this guide.

Add this exact inline group before the owner window declaration. The inline declaration is safest in Clarion 10 when the procedure is generated into a separate MEMBER module.

PromoData               GROUP

MaximumLength              ULONG

InputLength                ULONG

                        END
PromoDesignerInstance   ULONG
PromoCompletedInstance  ULONG
PromoDesignerResult     LONG
PromoDesignerStatus     LONG
PromoAutoload           BYTE

SIZE(PromoData) must equal 4256. Ensure AdvertLine and GLO:PromoTrailer can hold the complete returned encoded value; 4,096 bytes is recommended.

If the procedure does not already have a hidden notification control, add:

BUTTON(''),AT(0,0,1,1),USE(?CHUIComplete),HIDE

4. Prepare the designer

Add this local routine. Supply the current V4 encoded Promo-Trailer string directly; do not convert it through the former RTF editor or Promo queue.

PreparePromoDesigner ROUTINE
  CLEAR(PromoData)
  PromoData.Version = CHPT_ABI_VERSION
  PromoData.StructureSize = SIZE(PromoData)
  PromoData.BufferCapacity = CHPT_TEXT_CAPACITY
  PromoData.MaximumLength = 4095

  IF PromoAutoload
    PromoData.Flags = BOR(PromoData.Flags,CHPT_FLAG_AUTOLOAD)
  END

  PromoData.Text = AdvertLine

If CompuHost stores the accepted value directly in GLO:PromoTrailer, the final line can instead be:

  PromoData.Text = GLO:PromoTrailer

5. Open command - EVENT:Accepted

Replace the old Promo editor launch with this block:

IF PromoDesignerInstance
  MESSAGE('The Promo-Trailer Designer is already open.')
  CYCLE
END

DO PreparePromoDesigner

IF CHPT_GetAbiVersion() <> CHPT_ABI_VERSION
  MESSAGE('Promo Designer ABI version mismatch.')
  CYCLE
END

IF CHPT_GetDataSize() <> SIZE(PromoData)
  MESSAGE('Promo structure mismatch. Clarion=' & SIZE(PromoData) & |
          ' DLL=' & CHPT_GetDataSize())
  CYCLE
END

PromoDesignerStatus = CHPT_ValidateData(ADDRESS(PromoData))
IF PromoDesignerStatus <> CHPT_STATUS_OK
  MESSAGE('Promo data validation failed: ' & PromoDesignerStatus)
  CYCLE
END

PromoDesignerStatus = CHPT_OpenDesigner( |
  0{PROP:Handle}, |
  ADDRESS(PromoData), |
  ?CHUIComplete{PROP:Handle})

IF PromoDesignerStatus > 0
  PromoDesignerInstance = PromoDesignerStatus
ELSE
  MESSAGE('Unable to open Promo Designer: ' & PromoDesignerStatus)
END

6. Complete return event

Place this at the beginning of ?CHUIComplete / EVENT:Accepted, before existing Structured Setup consumers. The two completion queues are independent.

IF CHPT_ConsumeCompletion( |
    ?CHUIComplete{PROP:Handle}, |
    PromoCompletedInstance, |
    PromoDesignerResult)

  IF PromoCompletedInstance = PromoDesignerInstance
    CASE PromoDesignerResult

    OF CHPT_RESULT_OK
      ! Preserve the complete encoded buffer, including APP/NOAPP tags.
      AdvertLine = PromoData.Text
      GLO:PromoTrailer = AdvertLine

      PromoAutoload = CHOOSE( |
        BAND(PromoData.Flags,CHPT_FLAG_AUTOLOAD) <> 0, |
        1, |
        0)

      ! Persist AdvertLine and PromoAutoload using the normal V4
      ! configuration-save path here, if that path is not automatic.

      GLO:PromoChanged = 1
      POST(Event:ResetRotationScroller,,ScrollerWindow)

    OF CHPT_RESULT_CANCEL
      ! Cancel and title-bar X leave caller data unchanged.
    END

    PromoDesignerInstance = 0
  END
END

! Existing Structured Setup action/change/completion handling follows.

Empty is valid: when the user accepts an empty designer, PromoData.Text is empty and the code above clears the current Promo-Trailers. Do not wrap this callback in IF CLIP(LOC:RTFTempText) <> ''.

7. Tag and line rules

ItemRequired behavior
Physical linesEach nonblank CR/LF-delimited line is one Promo-Trailer. The DLL omits blank lines when OK is accepted.
<APP>Preserve unchanged for downstream routing.
<NOAPP>Preserve unchanged for downstream routing.
Formatting tagsPreserve color 0-9, Bold, Italic, and Underline tags returned by the DLL.
Clarion literalsWrite a runtime <APP> tag as '<<APP>' in Clarion source because Clarion doubles the literal less-than character.
Returned bufferPromoData.Text already contains the proper runtime single less-than characters. Assign it directly; do not double or replace them.

Remove from the V4 callback: all FREE(GLO:PromoQueue), ADD(GLO:PromoQueue), PMQ:PromoMessage, line splitting, and ReplaceStr calls that remove APP/NOAPP.

8. File and window behavior

  • Load and Save are handled entirely by the DLL and operate on .PRM files.
  • The first selector opens in the launching application's folder.
  • After a successful Load or Save, the DLL remembers the last folder per Windows user at HKCU\Software\Karaokeware\CHTheme\PromoDesigner\LastPrmFolder.
  • Only the encoded Promo-Trailer text is stored in the file. The caller receives that text through PromoData.Text after OK.
  • The Auto-load checkbox is returned separately in CHPT_FLAG_AUTOLOAD.
  • The normal window rectangle is stored as WindowRect under the same registry key and constrained to the current primary work area when restored.

9. Owner close protection

Do not destroy the callback control or PromoData while the modeless designer remains open. In the owner procedure's EVENT:CloseWindow:

IF PromoDesignerInstance
  MESSAGE('Close the Promo-Trailer Designer before closing CompuHost V4.')
  CYCLE
END

If Structured Setup shares the owner and callback, combine both guards:

IF DialogInstance OR PromoDesignerInstance
  MESSAGE('Close Setup or the Promo-Trailer Designer first.')
  CYCLE
END

10. Build and acceptance test

  1. Regenerate the application from the Clarion IDE so embed changes are retained.
  2. Build CompuHost V4 Win32 Release and resolve every new warning or error.
  3. Confirm the runtime DLL hash matches the release candidate shown above.
  4. Open the designer with existing formatted, APP, and NOAPP content. Confirm tags are hidden and formatting is rendered.
  5. Exercise Bold, Italic, Underline, colors, keyboard shortcuts, Undo/Redo, Clear, resizing, and hover feedback.
  6. Use Load and Save; confirm .PRM content round-trips and the last folder is recalled.
  7. Press Cancel and confirm the application values and Auto-load state remain unchanged.
  8. Press Set Promo-Trailers and Exit; confirm the complete encoded value and Auto-load flag are accepted.
  9. Reopen and confirm the accepted formatting and routing tags reconstruct exactly.
  10. Accept an empty editor and confirm current Promo-Trailers clear correctly.
  11. Confirm the rotation scroller receives Event:ResetRotationScroller.
  12. Restart CompuHost and verify the V4 persistence path restores the accepted text and Auto-load state.

Release-candidate boundary

This guide documents the approved integration contract. Staging the DLL does not itself modify CompuHost application embeds. Apply the Clarion changes through the Application Generator embeds, regenerate, compile, and test before designating the candidate as production.
